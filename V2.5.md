# Cultivo Flora V2.5

## Objetivo

V2.5 conserva el control local del Wemos y añade, de forma incremental, un dominio local para gestión y trazabilidad del cultivo. La versión estable vive en `APP/`; esta línea se desarrolla solamente en `APP-V2.5/`.

## Arquitectura

- HTML, CSS y JavaScript vanilla, sin bundler.
- `app.js`: comunicación y UI existente del Wemos.
- `energy.js`: histórico eléctrico independiente.
- `cultivo-models.js`: enums, normalización, validaciones y cálculo de dosis.
- `cultivo-db.js`: repositorio IndexedDB del dominio de cultivo.
- `cultivation.js`: cultivo activo, espacios, lotes y cambios de etapa.
- `products.js`: catálogo, búsqueda y activación/desactivación de productos.
- `recipes.js`: recetas, versiones inmutables, snapshots y calculadora de dosis.
- `www/`: copia generada por `npm run web:sync`; no se edita manualmente.

## Persistencia

Base: `flora-cultivo-db`. Versión de esquema: `1`.

Stores: `cultivations`, `spaces`, `lots`, `plants`, `products`, `recipes`, `recipeVersions` y `activities`.

Las migraciones se agregan incrementalmente en `migrate()` mediante bloques por versión. Nunca se destruye la base para actualizar el esquema. Los booleanos `active` se acompañan internamente con `activeKey` (`1` o `0`) porque los booleanos no son claves válidas de IndexedDB.

`cultivo-energy-db` y las claves actuales de conexión/energía permanecen sin cambios.

## Modelo y snapshots

Las recetas tienen una identidad lógica y versiones inmutables. Cada versión conserva snapshots mínimos de los productos. Una actividad futura guardará en `details.recipeSnapshot` la composición, dosis y cantidades calculadas usadas realmente; el historial no dependerá del estado actual de productos o recetas.

La aplicación presenta cuatro destinos principales en móvil: Inicio, Cultivo, Recetas y Control. Recetas contiene las subsecciones Productos y Recetas. Las opciones Arduino secundarias continúan accesibles desde Control y desde la navegación de escritorio.

Solo puede existir un cultivo activo como contexto general. Activar otro finaliza el anterior sin eliminarlo. Sus espacios y lotes se conservan y pueden desactivarse; la etapa del lote es independiente del nombre del espacio.

Crear una receta genera atómicamente su versión v1. Los cambios de metadata actualizan la identidad; los cambios de composición, dosis, pH, EC o notas de versión generan una nueva versión y mantienen las anteriores en solo lectura. Para riego, la calculadora escala exclusivamente `g/L` y `ml/L`; las demás unidades se muestran sin inventar conversiones.

Las etapas de lote son: `mother`, `clone`, `rooting`, `vegetative`, `flowering`, `harvest` y `finished`. Una planta individual es opcional y no tiene UI todavía.

## Separación del Arduino

El Wemos continúa siendo responsable de sensores, actuadores y automatización. Productos, recetas, cultivos, lotes y actividades viven en la aplicación. Las recetas podrán alimentar un motor de automatización futuro, pero no se envían al Arduino en esta fase.

## Desarrollo

```bash
npm install
npm run dev
npm run test:domain
npm run web:sync
npm run android:sync
npm run android:open
```

El servidor queda disponible en `http://127.0.0.1:8081/`.

Build debug:

```bash
cd android
export JAVA_HOME="$HOME/Library/Java/JavaVirtualMachines/jbr-21.0.11/Contents/Home"
./gradlew assembleDebug
```

El wrapper actual compila con JDK 21. El JBR 25 incluido en algunas versiones de Android Studio no es compatible con este Gradle.

Identidad Android:

- App ID: `com.cultivo.flora.v25`
- Nombre: `Cultivo Flora V2.5`
